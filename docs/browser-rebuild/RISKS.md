# Browser rebuild risks

Scale: impact and likelihood are low, medium, or high before mitigation.

| Risk | Impact | Likelihood | Mitigation and acceptance evidence |
|---|---|---|---|
| Chrome does not start or opens the wrong profile | High | Medium | Use a fixed executable selection policy, one new private profile per session, `DevToolsActivePort`, startup deadline, process-exit capture, and command-line diagnostics. Test missing binary, no display, unwritable profile, early exit, and two concurrent starts. Never retry with the user profile. |
| CDP endpoint is exposed or attached by another local process | High | Low–medium | Bind debugging to `127.0.0.1`, use a random kernel port, keep the endpoint inside authority state, use private profile and runtime directories, and never return the WebSocket URL to clients. For stronger production isolation, use a private network namespace or pipe transport if Chrome support and packaging permit it. Verify effective listening address. |
| CDP has version-specific behavior or missing domains | Medium | Medium | Detect product and protocol version, use stable domains, keep protocol calls small, and run fixtures against supported Google Chrome and Fedora Chromium. Fail a capability explicitly. Do not hide failure through another agent or active tab. |
| Browser target identity changes during navigation, prerender, popup, or crash | High | Medium | Maintain target and flattened CDP session registries. Listen for target create/change/destroy/crash and top-frame commit. Increase document generation and invalidate observations and handles. Keep a popup private until attachment, required domains, and a final allowed top-level URL check complete. Test renderer crash, popup, close, navigation, and a forbidden commit during popup attachment. |
| Wayland and X11 launch or window behavior differs | Medium | Medium | CDP coordinates stay in page CSS space. Test Chrome under native Wayland and XWayland. Diagnose graphical environment. Do not depend on OS focus for authority. Treat window placement as best effort. |
| Cursor overlay is removed, covered, duplicated, or absent from screenshots | Medium | Medium | Install with a preload script, use a stable ID and maximum z-index, set `pointer-events:none`, verify before action/capture, and reinject after navigation. Add fixtures for mutation, dialog top layer, iframe, fullscreen, canvas, shadow DOM, and page CSP. Report degraded overlay state rather than claiming visibility. |
| Overlay changes page behavior | Medium | Low–medium | Use one fixed non-interactive node, no layout size, no event interception, and minimal globals. Prefer an isolated world if screenshot capture includes it. Test hit testing, fixed headers, pointer events, and page scripts that enumerate globals. |
| Animated content makes screenshot coordinates stale | High | High | Require observation ID, bounded monotonic lease, owner/target/document/viewport generations, scale, scroll, epoch, and bounds. Repeat checks after path and before irreversible input. Do not require byte equality. Return typed stale state and request a new frame. |
| Freshness policy rejects valid actions too often | Medium | Medium | Use a reviewed 60-second production default bounded to 10–120 seconds so model reasoning and visible movement fit. Keep animation-tolerant structural checks and separate DOM lifetime. Measure delayed actions and show exact `validUntil`. |
| Device-pixel ratio, browser zoom, fractional display scale, or multi-monitor layout causes coordinate error | High | Medium | Define action coordinates in CSS viewport pixels. Record DPR and CSS viewport in every observation. Reject changes. Keep screenshot encoding and viewer scaling explicit. Test 1.0, 1.25, 1.5, and 2.0 desktop scales, browser zoom changes, and monitor moves. Do not reuse this mapping for future OS input. |
| Disposable profile is corrupted or locked | Medium | Medium | One session owns one profile. Record ownership metadata. On close, stop the process before removal. On startup, clean only verified orphans. Never share, repair, or reuse another session’s profile. Test crash and stale lock files. |
| Browser or renderer crashes during input | High | Medium | Mark host or target disconnected, stop frame capture, fail or cancel operations, release held-button state if possible, and publish lifecycle events. Do not reconnect to a different target silently. Test crash during move, drag, click dwell, typing, navigation, and screenshot. |
| Cross-agent action or frame leakage | Critical | Low–medium | Validate full owner/session/browser/tab/target lineage and control epoch for every operation and frame read. Use constant-shape ownership errors. Partition artifacts and subscriptions. Test wrong values at every address field and valid foreign IDs. Phase 0 proves target rejection; production must also protect frame and artifact reads. |
| Workspace selection becomes authority | High | Medium | Keep selected session only in workspace view state. All control calls still carry full identity and pass authority checks. Switching never changes controller. Test rapid switch while frames and actions arrive. |
| Screenshot bandwidth or queues grow without bound | High | High | Default to about 2 fps selected/recent and a lower idle rate. Allow one pending capture per tab. Keep only the latest pending frame per consumer. Bound inline size and artifact retention. Measure encoding time, bytes per second, dropped frames, CPU, and memory. |
| Two Chrome processes use too much memory | High | High | Phase 1.2 measured browserd and each Chrome tree separately for two hours. Total PSS was 868,923–984,470 KiB and did not plateau: full/final-hour/final-30-minute slopes were +41,613/+61,198/+29,914 KiB/hour. Browserd, bounded stores, process counts, and Chrome session B were nearly flat late. Most final-hour growth was in Chrome session A. Keep one process tree per session. Allow Phase 2 development behind the reversible switch, but require credible plateau evidence or a tested bounded Chrome session recycling and recovery policy before default routing. |
| User takeover races with an agent action | High | Medium | Increment control epoch at takeover and return. Cancel queued old-epoch actions. Stop unsent path samples. Report already-dispatched effects. Reject all old-epoch results. Test the agent-user-agent ABA sequence and takeover during drag. |
| User assumes the page cursor is the Linux OS cursor | Medium | Medium | Label it “virtual mouse.” Keep it visible in screenshots and workspace. State that CDP events are not OS-level trusted input. Put optional Linux OS control in a later explicit phase. |
| AgentCursor upstream change breaks behavior or licensing | Medium | Low | Selectively vendor one exact MIT commit with license, source list, and local changes. Do not use a floating dependency. Review and test any update manually. |
| AgentCursor extension becomes required unexpectedly | Medium | Low | Phase 0 covers required capabilities without it. Add an extension only after a fixture demonstrates a named CDP gap. Review permissions, target authority, packaging, and Chrome extension policy before adoption. Never use active-tab fallback. |
| Local service transport permits unauthorized reads or control | Critical | Medium | Gate 0 uses a `0700` runtime directory, `0600` ready-state descriptor and unique request socket, kernel-owned abstract AF_UNIX lifetime ownership, random per-start secrets, one-time connection binding, connection-scoped frames, and actor-scoped objects. Production accepts only trusted `webxd`; Pi/model requests do not receive the descriptor. Hostile same-UID code remains outside the boundary unless a later separate-user or sandbox design is adopted. Keep secrets out of URLs and logs. |
| Unsafe Chrome flags enter configuration | Critical | Low–medium | Configuration chooses an executable and reviewed options, not arbitrary flags. Validate an allowlist. Reject `--no-sandbox`, broad web-security/site-isolation disablement, certificate bypass, and normal-profile paths. Test the effective process command line. |
| Page secrets leak through diagnostics or artifacts | High | Medium | Bound outputs. Do not log cookies, storage, headers, profile paths, raw CDP endpoints, or screenshot bodies. Owner-scope artifacts, store hashes, use short retention, and keep directories private. Browser debugging remains explicit. |
| Cancellation claims rollback after side effects | High | Medium | Track operation state separately from `not-dispatched`, `partially-dispatched`, or `dispatched`. Cancel queued work fully. Stop future path samples and release held input when possible. Never claim click or navigation rollback. |
| Fedora packaging cannot inherit a graphical session | High | Medium | Use a user service or desktop activation with documented environment import. Doctor checks display variables and bus access. Test login, reboot, lock screen, remote shell, and no-display cases. Keep search/read services independent. |
| Fedora Chromium differs from Google Chrome | Medium | Medium | Prefer Chrome and make executable configurable. Report exact product/version. Run deterministic gates on both. Document codec, enterprise policy, release, wrapper, and user-agent differences. Avoid extension dependence. |
| Page-driven navigation bypasses WebX destination checks | Critical | Medium | Require production Chrome to use the reviewed loopback forward proxy with no implicit loopback bypass. Reject local names and any non-public or mixed DNS answer. Pin each connection to a validated IP. Disable QUIC and non-proxied WebRTC UDP. Fail session creation without healthy egress. Test explicit URLs, redirects, clicks, and popups. |
| Broker navigation authorization is replayed for another actor or daemon | High | Low | Sign the runtime instance, actor, stable operation ID, normalized URL, egress binding, expiration, and nonce with the owner-only descriptor secret. Verify all fields in browserd before dispatch. Replace secrets and runtime identity on restart. |
| Browser screenshot base64 leaks into model text or caches | High | Medium | POST observation returns metadata only; exact GET reads one live artifact. Verify canonical base64, bytes, digest, media type, and decoded dimensions, then move bytes through `artifactPayload`. Keep no full webxd session buffer. Route-aware idempotency and diagnostics require zero image bytes in the general map. |
| Image pixels differ from CSS viewport pixels | High | High | Record actual decoded image dimensions and CSS dimensions in the observation. Convert inside browserd after resolving that exact observation. Validate source bounds and both drag endpoints. Test DPR 1, 1.25, 2, and fractional dimensions. |
| Tauri embeds remote content and expands the trust boundary | High | Low | Bundle local UI only. Display screenshots as image data. Apply a strict content security policy. Reject remote navigation. All page interaction remains in the separate Chrome process. |
| Cleanup deletes the wrong directory | Critical | Low | Create profiles only under a dedicated private root. Store random ownership metadata and canonical path. Refuse cleanup outside that root or without matching metadata. Stop process first. Test symlinks and path traversal. Phase 0 uses `mkdtemp` and tracks only returned paths. |

| Fragmented NDJSON corrupts identity or unbounds queues | High | Medium | Give every connection one persistent fatal UTF-8 decoder. Independently bound one frame, incomplete bytes, pending requests, subscriptions, and outbound bytes. Use socket drain, pre-write abort, bounded admitted cancellation, and reject all pending work on disconnect. |
| Webxd restart loses or remaps browser ownership | High | Medium | Rehydrate only through actor-bound browserd `session.list`. Pin descriptor-dependent signing and request execution to one runtime connection. Purge local sessions, observations, and subscriptions on runtime replacement and reject old IDs. |
| Active frame capture leaks after unsubscribe failure | High | Medium | Keep subscriptions open through idle pruning, update activity on frames, share teardown, retain local state until remote commit, and close the full actor connection when confirmation is lost. Browserd connection cleanup removes remote subscriptions. |
| An unrelated listener impersonates healthy browser egress | Critical | Medium | Require a bounded exact 204 branded health response and agreement on egress binding ID. Probe independently on session creation. Do not claim this protects against hostile same-UID code. |
| Page starts a download without a public download tool | High | Medium | Require browser-wide Chrome download deny with events, cancel starts, accept no caller-selected path, and fail host startup/operation closed when enforcement is unsupported. Verify no file remains. |

## Residual risks after Phase 2B

Phase 2B makes the new route reliable only behind the non-default development switch. These items remain gates before production-default routing:

1. Add the production Tauri frame bridge and human takeover. Keep workspace selection separate from authority.
2. Test Google Chrome when it is installed. Current evidence on this host covers Fedora Chromium only.
3. Test fractional desktop scale, multiple monitors, fullscreen, PDF, top-layer visual precedence, and aggressive overlay mutation cases.
4. Set reviewed production session, CPU, PSS, frame-rate, artifact, and operation budgets. Phase 1.2 gives two-hour bounds but not a PSS plateau. Meet ADR-012 with stronger representative plateau evidence or a tested bounded Chrome session recycling and recovery policy before default routing.
5. Package and supervise the secure egress proxy with browserd. Add final systemd user service, graphical-session, upgrade, and rollback tests.
6. Keep cross-origin out-of-process iframe DOM fallback unsupported until a separate authority and coordinate design is reviewed. Same-origin iframe fallback is covered.
7. Hostile same-UID code remains outside the ADR-011 boundary. Use a separate Unix user or stronger sandbox only if that threat enters scope.

The Phase 0 viewer is not a security reference. The Phase 2B native route does not use Tauri. The 30-minute process soak does not resolve ADR-012. See `PHASE2B-RESULTS.md`, `ADR-015-OBSERVATION-LEASE-AND-MOTOR-TIMING.md`, and `ADR-016-SCREENSHOT-TRANSFER-AND-IDEMPOTENCY.md`.
